# GTA VI research tool atlas

**Where to start.** For an audio bank, inspect its stream table with rpf9-audio. For a typed binary resource, compare rpf9-explorer's PSIN reader with an independently predicted field. For a world placement, resolve its identity and transform before putting a point on a map. The [README's ten experiments](../README.md#ten-things-to-build-from-the-data) give an acceptance test for each output.

## Six related repositories

The links below pin the source or notes inspected on 21 November 2026. Source inspection establishes what a project implements or documents. A local compatibility result requires testing the exact revision, input type and output. No third-party release binary was installed for this survey.

| Project | Useful part | First comparison to make locally |
|---|---|---|
| **jaylikesbunda/rpf9-audio** | Python definitions for AWC streams, chunks and channel formats; separate code for Opus packaging. [AWC reader](https://github.com/jaylikesbunda/rpf9-audio/blob/33c083971e2f38cc35748338f55018a7901a019a/src/rpf9_audio/awc.py) · [Ogg Opus writer](https://github.com/jaylikesbunda/rpf9-audio/blob/33c083971e2f38cc35748338f55018a7901a019a/src/rpf9_audio/oggopus.py) | Compare two independent readings of one bank's channel count and sample count. Use a separate metadata join to establish its title. |
| **breadbbbb/rpf9-explorer** | A Windows explorer with separate components for PSIN inspection and model-to-texture bindings. [PSIN inspector](https://github.com/breadbbbb/rpf9-explorer/blob/48557ead00601d3757ba12b894f2595c4faad2a5/Core/PsinMetadata.cs) · [Binding code](https://github.com/breadbbbb/rpf9-explorer/blob/48557ead00601d3757ba12b894f2595c4faad2a5/Core/ModelTextureBindings.cs) | Compare a reported field or texture reference to the stored offset, field width and target bounds. Check a second resource before extending the interpretation. |
| **rpatty-dev/PercyStar** | Rust implementations for RDNA2 shader-cache inspection, textures and audio. [Shader reader](https://github.com/rpatty-dev/PercyStar/blob/00ee3bab6c8204965f62662212f862245dbabaf0/src/rdna2.rs) · [Texture reader](https://github.com/rpatty-dev/PercyStar/blob/00ee3bab6c8204965f62662212f862245dbabaf0/src/tex.rs) | Validate table bounds and pipeline references. A successful parse still leaves shader translation and rendered output to test. |
| **offs/rpf9-extract** | Rust readers for container layout and payload carving. [Container layout](https://github.com/offs/rpf9-extract/blob/46ca608975b749fc3e77a62435d46fdc115a97e0/src/container.rs) · [Carver](https://github.com/offs/rpf9-extract/blob/46ca608975b749fc3e77a62435d46fdc115a97e0/src/carve.rs) | Check whether the proposed offset came from directory metadata or from scanning payload bytes. Two carvers finding the same header cannot independently verify its filename. |
| **walkthestars/GTA6-Asset-Info** | SixNG format notes cover TTPF texture stores, placement records and interiors. Treat the notes as field hypotheses and keep their revision with the test. [Texture-store notes](https://github.com/walkthestars/GTA6-Asset-Info/blob/bad5bc2180ade416eafdb50aa21e21eeec5adbda/formats/05-ttpf.md) · [Placement notes](https://github.com/walkthestars/GTA6-Asset-Info/blob/bad5bc2180ade416eafdb50aa21e21eeec5adbda/formats/09-placements.md) | Predict the next boundary or transform before reading the payload. Retain failed predictions as well as matches. |
| **wpenistone/leonida_gis** | Community GIS tooling for georeferencing and reviewing a Leonida map. Its georeferencing script is useful downstream of a placement reader. [Georeferencing script](https://github.com/wpenistone/leonida_gis/blob/7e3d9b5bc4ae2b09fd60316da0001d706dba10dc/scripts/01_georeference_base.py) · [Data sources](https://github.com/wpenistone/leonida_gis/blob/7e3d9b5bc4ae2b09fd60316da0001d706dba10dc/DATA_SOURCES.md) | Calibrate on known landmarks and measure error on withheld ones. Record the map's provenance before using it as an independent reference. |

## Tools by research stage

| Stage | Use now | Future use and dependency |
|---|---|---|
| Package and executable intake | [Project inventory](../tools/inventory.py), [PE inspector](../tools/inspect_pe.py), and [DUMPBIN](https://learn.microsoft.com/en-us/cpp/build/reference/imports-dumpbin?view=msvc-170) for an independent import listing | Compare a matching authorized executable to its trusted catalog and select a supported host or desktop build target. |
| Archive boundaries | [Stream probe](../fixture/rpf.py) verifies checksums; [directory probe](../fixture/directory_probe.py) tests two offset/size predictions | Add a typed parser only after its layout predicts the result on a held-out resource. |
| Video and audio | [RAD Video Tools](https://www.radgametools.com/binkfaq.htm) for supported Bink input, [FFmpeg and ffprobe](https://ffmpeg.org/documentation.html) for conversion and verification | Compare supported bank variants with [vgmstream](https://vgmstream.org/). Preserve alternate streams and check decoded sample totals before labeling an export complete. |
| Models, characters and animation | [CodeWalker](https://github.com/dexyfex/CodeWalker) provides public **GTA V** reader implementations. [Sollumz](https://github.com/Sollumz/Sollumz) supplies a **GTA V** Blender workflow. | Once a GTA VI layout has been independently decoded, use Blender to inspect geometry, skeleton binding, animation timing and material assignments. GTA V support establishes a comparison baseline. |
| World coordinates | A table of verified placements can be inspected before a base map exists. Preserve source coordinates and axis conventions. | Use [GDAL](https://gdal.org/en/stable/programs/gdaltransform.html) and [QGIS](https://qgis.org/) when a transform and control points are available. Publish uncertainty alongside any spatial alignment claim. |
| Indexes and joins | [SQLite](https://sqlite.org/) can store one row per source range, decoded resource or reference, with separate tables for candidate names. | Use joins to find reused shaders, duplicate props or ambiguous names. Track unresolved and many-to-many matches explicitly. |
| Desktop runtime and GPU | The [GDK triangle](../demo/gdk/README.md) provides a reproducible desktop rendering baseline. | Use the D3D12 debug layer and [PIX](https://learn.microsoft.com/en-us/windows/pix/gpu-captures/gpu-captures-overview) once a supported desktop renderer submits real work. Compare a readback buffer or draw with a trusted reference. |

For each comparison record the tool revision, input identity, units, observed result and whether the second method shares the same parser. Keep game-specific inputs, outputs and logs local. [Full workflow](handbook.md) · [GTA V comparison by data type](data-types.md)
