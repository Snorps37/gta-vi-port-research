# GTA VI data types | What we know, what GTA V tells us, and what is missing

**Public research status · 21 November 2026.** GTA V has a released Windows build and independently inspectable PC tooling. Rockstar lists GTA VI for Xbox Series X|S and PlayStation 5. Project NATIVE has demonstrated static inspection and a desktop graphics baseline. It has yet to demonstrate a GTA VI game frame, controllable scene, or gameplay frame rate on Windows. [GTA V PC release](https://www.rockstargames.com/newswire/article/7551a7k917554a/free-upgrade-for-grand-theft-auto-v-on-pc-now-available) · [GTA VI platforms](https://www.rockstargames.com/VI)

**How to read the comparison.** The GTA V column cites named features of a pinned CodeWalker revision or publisher documentation. GTA V Legacy and Enhanced are distinct PC releases; a reader for one layout cannot establish compatibility across editions. The progress column records methods or milestones. “Open” means Project NATIVE has no verified result for the question in that row. No file-by-file comparison of matched publisher builds is available here. Differences in the games’ internal formats, counts or content remain unknown unless an independent public reference supports them.

## Package, code and storage

| Data type | GTA V baseline and relevant difference | Project NATIVE progress | Missing evidence and next test |
|---|---|---|---|
| Executable | GTA V has a supported Windows executable. An Xbox-targeted executable requires a compatible loader, ABI and services even on an x64 CPU. [Rockstar PC requirements](https://support.rockstargames.com/articles/lMQXeP2Z1mN3g9oZiBZFR/grand-theft-auto-v-pc-system-requirements) | The [PE inspector](../tools/inspect_pe.py) recovered ordinary import providers on installed x86 and x64 Windows images. | Obtain a matching authorized program or desktop source target; verify identity and show initialization on the intended host. |
| Runtime libraries | The shipped Windows game has a desktop dependency environment. An identical DLL or function name on Xbox is insufficient evidence of equivalent behavior. | Static PE headers and provider names can be inspected. | Identify actual runtime calls, calling conventions, ownership and error semantics; validate one required operation. |
| Launch manifests and configuration | Windows and Xbox deployment can select different executables and target families. A title or version string alone cannot authenticate either build. [GDK executable selection](https://learn.microsoft.com/en-us/gaming/gdk/docs/reference/system/microsoftgameconfig/elements/microsoftgameconfig-element-executable) | The project demonstrates entry-path presence and absence checks. | Match an independently trusted package identity, program and content version. |
| Archive directory and compressed pages | CodeWalker explicitly checks an RPF7 header. The separate RPF9 reader illustrates a different header/table model. Applying either reader to a specific GTA VI edition requires independent validation. [RPF7 implementation](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/RpfFile.cs) · [RPF9 header reader](https://github.com/offs/rpf9-extract/blob/46ca608975b749fc3e77a62435d46fdc115a97e0/src/container.rs) | Public probes check offset/size predictions on two entries and validate bounded zlib page runs. | Verify names and ranges against an independent writer or trusted index, including an entry withheld when choosing the rule. |
| Streaming indexes and texture pages | GTA V tooling can read texture dictionaries. A dictionary entry, disk extent and resident GPU texture have different identities. [Texture dictionary reader](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YtdFile.cs) | Range checks and a method for validating monotonic streaming boundaries have been exercised. | Link a stable resource ID to a descriptor and all mip ranges, then compare decoded pixels after eviction and reload. |
| System image, catalogs, resource indexes and alignment files | Packaging depends on the distribution and target. The GTA V PC baseline supplies no general decoder for Xbox system images. | Package-level identification and content-integrity checks have been distinguished from publisher authentication. | Identify the format of each opaque region, obtain the supported reader or authorized mount, and verify a logical file against a trusted reference. |
| Package art, UI and localized text | GTA V tooling includes a GXT2 text reader. A shell logo, localized label and rendered in-game menu are different resources. [GXT2 reader](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/Gxt2File.cs) | Image dimensions and typed configuration can be checked independently. | Resolve a UI key for two locales and demonstrate the intended screen. A recognized image header settles only its container type. |

## Rendering, world and movement

| Data type | GTA V comparison | Project NATIVE progress | Missing evidence and next test |
|---|---|---|---|
| Shaders, materials and pipeline state | GTA V tooling groups FXC shaders. GTA V Enhanced also adds rendering features over Legacy, so a single “GTA V shader format” is too broad a baseline. [FXC reader](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/FxcFile.cs) · [Rockstar PC update](https://www.rockstargames.com/newswire/article/7551a7k917554a/free-upgrade-for-grand-theft-auto-v-on-pc-now-available) | Cache range and pipeline-reference validation have been exercised; the [desktop GDK sample](../demo/gdk/README.md) renders a triangle. | Compare a compute output buffer and a textured draw on the desktop GPU against known reference outputs. Shader indices alone cannot verify translation. |
| Props, buildings and models | GTA V tools distinguish drawable geometry from archetype definitions and placed instances. [Drawables](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YdrFile.cs) · [Archetypes](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YtypFile.cs) | Research distinguishes library registrations from individual models and placements. | Join a placement to one stable model ID, geometry, material and LOD chain. Deduplicate by model for a unique-prop count. |
| Maps, terrain and interiors | In GTA V a map placement can refer to an archetype defined elsewhere. [Map reader](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YmapFile.cs) | Typed cross-archive location and placement matching has been exercised. | Reproduce a full placement-to-renderable chain and check transform, interior visibility and streaming transitions. |
| Collision and navigation | GTA V readers distinguish collision bounds and navigation meshes. [Collision bounds](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YbnFile.cs) · [Navigation](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YnvFile.cs) | Open at playable-scene level. | Validate polygon indices, coordinate frames and adjacency. Compare one collision contact and one path request against a reference. |
| Vehicles | GTA V has separate vehicle configuration and handling-related resource families, including layout and variation definitions. [Vehicle layouts](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/VehicleLayoutsFile.cs) · [Vehicle definitions](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/VehiclesFile.cs) | Open for an end-to-end vehicle. | Resolve a vehicle ID to its model, seat layout, collision and physics parameters; verify seating and movement. |
| Animation and skeletons | GTA V has a clip-dictionary reader. Clip names alone cannot establish skeleton compatibility. [Clip dictionary](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YcdFile.cs) | Animation has been distinguished from scene and mission metadata. | Resolve one clip to its rig; verify bone order, bind pose, timebase and root motion. |
| Lighting, effects and weather | GTA V tooling includes separate distant-light and particle-effect readers. [Distant lights](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/DistantLightsFile.cs) · [Particles](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YptFile.cs) | The graphics baseline exercises basic presentation. Effect parity remains open. | Validate one light and one particle effect under fixed camera, exposure and time settings before attributing a visual difference to either game. |

## Characters, stories and media

| Data type | GTA V comparison | Project NATIVE progress | Missing evidence and next test |
|---|---|---|---|
| Characters, pedestrians and population | GTA V tooling distinguishes pedestrian definitions from variation data. A character can reuse a model and have several schedules. [Ped definitions](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/PedsFile.cs) · [Ped variation](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/PedFile.cs) | Schedule and body-variation catalogs have been distinguished from character identities. | Join persistent character IDs, spawn definitions and models. Named characters, crowd archetypes and spawned instances need separate totals for either game. |
| Clothing, outfits and accessories | GTA V has ped variation and character cloth data. A cloth simulation resource and a purchasable garment answer different questions. [Character cloth](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YldFile.cs) | Research has identified the distinction between wardrobe-related settings, shop roles and actual items. | Link a wearable ID to slot, drawable, texture variants and outfit membership. Verify equip, removal and reload. |
| Weapons, inventory and loadouts | A definition, an attachment and a saved loadout require different counting rules in both games. A matched inventory schema for the two titles is unverified. | Typed inventory fields and loadout registrations have been examined. | Resolve item identity across definitions and loadouts and verify behavior for a single equipped item. |
| Missions, replay catalogs and scripts | A replay menu can enumerate IDs without exposing VM instructions. No matched GTA V/VI mission-bytecode or native-call ABI comparison has been verified by this project. | Structured catalog rows and typed cross-record ID matches have been distinguished from executable logic. | Resolve a catalog ID to a supported runtime entry, observe an event and verify completion state. |
| Story choices and endings | Comparing story breadth requires the same definition of a branch in each game. A chapter label, alternate image or replay option does not establish an outcome. | A condition-and-successor test has been defined. Branch execution remains open. | Demonstrate a shared starting state, two distinct choices and two persisted outcomes. Story and ending totals remain unresolved. |
| Movies, cutscenes and dialogue | GTA V tooling has a cutscene structure reader. A staged cutscene may use animation, camera and sound; an encoded clip can also belong to a menu. [Cutscene reader](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/CutFile.cs) | Movie frame indexes, durations and duplicate detection have been validated as methods. | Connect a verified clip range or scene definition to a named playback event. A clip count cannot measure story cutscenes or unique conversations. |
| Audio banks, music and speech | GTA V tooling distinguishes AWC streams from associated audio metadata. [AWC reader](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/AwcFile.cs) · [Audio metadata](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/RelFile.cs) | Video-container audio metadata can be inspected. General bank decoding and in-game mixing remain open. | Join an event to a bank and stream, validate codec, channels, timing and routing, then compare playback. |
| Input, saves and platform services | A released PC build provides desktop implementations. That alone establishes no cross-title save compatibility or shared Xbox service ABI. | The project has an interactive desktop sample; title-specific persistence is open. | Reconnect a controller, save, restart, reload and verify the same player state under a supported account. |

## Which comparisons are ready to make?

**Ready today:** compare how the public PE inspector and Microsoft's DUMPBIN describe the same Windows binary; reproduce the archive probes against their existing tests; reproduce the GDK triangle. These have a concrete input, method and observable result. [Executable walkthrough](xbox-to-pc.md) · [Archive probes](../README.md#verify-a-compressed-stream-boundary) · [Desktop graphics baseline](../demo/gdk/README.md)

**Still open:** which game has more unique props, NPCs, garments, missions, choices or cutscenes; whether particular GTA V resource layouts carry over unchanged; and how GTA VI would perform on a desktop compatibility runtime. A defensible comparison needs the edition and platform on both sides, matched coverage, the same unit of counting and a way to detect variants or duplicates. The next useful milestone is to establish one comparable resource end to end before extending the method to a whole catalog.
